**Two design decisions worth knowing (both deviate from the literal plan, for the better):**
1. **Auth is resolved client-side via `GET /api/studio/me`, NOT in the root layout.** The plan's
   async-layout-`authed`-prop approach reads `cookies()` in the root layout, which taints **every** route
   to dynamic rendering once `STUDIO_AUTH_TOKEN` is set — losing static generation for the marketing pages
   (bad for CWV/SEO). Confirmed empirically (build flips `/ /about /page-2` ○→ƒ). The `me` route keeps them
   static (○). User explicitly chose this for SEO. The client gate is **visibility-only** — publish/merge/
   close all enforce `isStudioAuthed()` server-side (401), verified.
2. **Enter/exit edit is a HARD navigation** (`location.assign`), because the landing's `isEdit` is
   `useMemo(…,[])` and the Lenis/GSAP freeze only re-engages on a fresh mount.

**Merge detail that bit (now handled):** page + chrome share one document, so the overlay's capture-phase
click listener early-returns on `[data-studio-chrome],[data-studio-panel]` (else panel clicks would
deselect/get swallowed). And the fixed toolbar reserves its height on `<body>` via ResizeObserver
(WordPress admin-bar pattern) so it doesn't occlude the page's top content — a `full-review` peer agent
caught the occlusion (measured: `hero.textAlign` at y=12 behind a 75px bar on /about); fixed + re-verified.

- **New `EditableText` wrapper** (`components/studio/EditableText.tsx`) — wraps `<Text>`, owns the
  `data-content-path`, and applies per-block style from `useTextStyle` via inline CSS variables

  supplies the page slug + published `styles` map once per page. The single home for per-block styling.
- **Full design-system palette pickers** (`lib/content/colors.ts`) for text color + background — a

## Gotchas the next agent MUST know
- **Dev server: port 3002** (`npm run dev`). After big changes HMR goes stale → **restart** before browser-verifying (bit us repeatedly). Log: `/tmp/devserver.log`.
- **`tsc --noEmit` has pre-existing noise** (`@syscore/ui-library` internals + youtube-player `YT` globals). Filter to changed files; **`npm run build` is the real gate.**
- **tsx data-layer tests need `--conditions react-server`**: `npx tsx --conditions react-server tests/<f>.test.ts`. Without it, `import "server-only"` (transitively via `changeset.ts` → `sanitize-server.ts`) throws in plain Node.
- **Playwright** is imported by absolute path from the sibling beta repo: `file:///Users/nickzaremba/Documents/certainly/iwbi/onewell-standard-frontend/node_modules/playwright/index.mjs`. `localStorage.clear()` first; stub `/api/studio/preview` + `/api/studio/publish` to avoid real PRs. **For the in-place editor, Playwright drives the real page directly (no iframe) — drop the cross-frame `page.evaluate`/`frameLocator` dance; it's much simpler now.** (For drag, a real pointer-drag with computed coords works; keyboard input to the @dnd-kit sensor was unreliable — see `tests/reorder.e2e.mjs`.)
- **Auth:** `studio_auth` is an **httpOnly** cookie (not client-readable) → gate the pencil by passing a server-computed `authed` boolean from `app/layout.tsx` (server component) into the client mount. `isStudioAuthed()` (`lib/studio/auth.ts`) returns **true in dev when `STUDIO_AUTH_TOKEN` is unset** — so to test the *gate* you must set the token + clear the cookie. `StudioLogin` + `app/studio/layout.tsx` are reused.
- **Editor code currently ships to anon visitors** (`EditModeBridge` is statically imported by the 3 public pages). The in-place plan fixes this (centralize + auth-gate + `dynamic({ssr:false})`); verify the public `/about` bundle has no overlay/@dnd-kit chunk afterward.
- **Layout vocab is keyed by path globally**, not by (page, path) — `lib/content/layout-vocab.ts` has a note. Fine today (unique section keys); scope by page if two pages ever share a path.
- **Env for the live demo:** `ANTHROPIC_API_KEY` (AI "Ask AI" box; manual buttons work without it), `NEXT_PUBLIC_CLOUDINARY_CLOUD_NAME`/`_UPLOAD_PRESET` (image uploads).
